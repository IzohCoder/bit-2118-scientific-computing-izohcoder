# BIT 2118 Scientific Computing: technical report

## Scope and approach

The official assignment lists Tasks 2–20 and requires a baseline, a parameter/input change, interpretation, and a related real-world adaptation for every task. Each launcher in `code/` runs the PDF-style example, a changed case, and a related adaptation from `code/runner.py`. Captured console output is stored in `results/runs/`; generated figures are in `results/figures/`.

The reported quantities below come from the recorded execution of these programs. Timing results are illustrative because they depend on computer load and software versions. Demonstration data are synthetic or supplied by the PDF; none of the adaptation outputs should be read as field measurements.

## Method notes and limitations

- A residual checks whether a computed vector satisfies its equations; a small residual is useful evidence but does not by itself prove the model is appropriate.
- The LU example uses SciPy's pivoted LU factorization and reuses the factorization for multiple right-hand sides.
- Eigenvector scores are normalized absolute values for display; sign and scale of an eigenvector are mathematically arbitrary.
- Root solvers need valid brackets or suitable starting values. Multiple roots and convergence basins matter.
- Curve-fit prediction beyond measured input values is extrapolation and can be unstable, especially for polynomials.
- Continuous optimization permits fractional units. The integer search is included where discrete purchase counts make that distinction important.
- Random-number seeds make this run reproducible. A different seed or assumed probability distribution changes the Monte Carlo estimate.
